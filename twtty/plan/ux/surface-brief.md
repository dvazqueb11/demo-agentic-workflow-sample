# To-do application surface brief

## Job

Give a workshop participant a calm, immediately understandable shared to-do list so the product remains credible while the separate GitHub workflow demonstrates bounded remediation.

## Primary user

A workshop participant or customer engineer who understands ordinary task-list conventions and should not need product training.

## Operating mode

Operate. The surface supports frequent task creation and state changes; it is not a workflow-control dashboard.

## Information priority

1. Add a task.
2. See incomplete tasks and their completion state.
3. Complete, reopen, edit, or delete a task.
4. Filter the current list and understand empty, loading, error, and rate-limit states.
5. Recognize that the data is a public shared demo.

## Primary interactions

- Create a task from title and optional description.
- Toggle completion without losing list position.
- Open row actions for edit or delete.
- Filter by all, open, or completed.
- Retry recoverable loading errors.

## Required states

Loading, populated, filtered-empty, first-use empty, submitting, validation error, not found, rate limited, offline/network error, and successful mutation.

## Accessibility contract

Keyboard-first operation, semantic form controls and lists, visible focus, 44-by-44-pixel minimum targets, non-color completion cues, polite live status, programmatic errors, reduced-motion support, and WCAG 2.2 AA contrast.

## Out of scope

Accounts, personal workspaces, drag-and-drop ordering, due dates, tags, collaboration presence, workflow controls, agent chat, and remediation evidence inside the product UI.
